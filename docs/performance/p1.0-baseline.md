## SLO Interpretation

These are single-user database execution times, not endpoint p95/p99 results. They are valid for plan and buffer prioritization only. The direct SQL times are below the preliminary latency budgets except POS product search, but the product/OEM/POS command counts, deep offset behavior, and unbounded report materialization already fail their structural SLOs. Concurrency readiness remains unproven until P4.

## Measured P1.1 Candidates

1. Remove product-page and OEM N+1 reads before index work (52 commands for a 50-row page).
2. Split exact SKU/barcode/OEM routing from substring POS search; exact SKU/barcode currently use sequential scans.
3. Address POS search buffer cost and repeated exchange-rate reads (42-62 commands).
4. Replace deep offset navigation after bounded-query cleanup; the last product page spills temp blocks.
5. Bound report materialization and rate lookup count before report indexing.
6. Re-measure dashboard/document/history paths before selecting tenant-first composite indexes.
